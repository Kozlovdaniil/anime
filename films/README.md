# Локальный онлайн-кинотеатр (Symfony + Docker, два источника)

> **Отдельный инстанс.** Это копия проекта для каталога кино/сериалов на **Kodik API**.
> Работает независимо от основного сайта:
>
> | | Значение |
> |---|---|
> | Сайт | <http://localhost:8081> (`APP_PORT` в `.env`) |
> | Docker-проект | `films` → `films-app-1`, `films-database-1`, `films-nginx-1` |
> | Том БД | `films_database_data` (внешний, уже создан) |
> | Подсеть | `172.29.0.0/24` |
> | БД | `films` / `films` / `films` |
> | Токен Kodik | `.env.local` (в git не попадает) |
>
> Консольные команды запускать от пользователя контейнера — иначе кеш создастся
> от `root`, и php-fpm не сможет в него писать:
>
> ```bash
> docker compose exec -u daikzlex app php bin/console <команда>
> ```

Локальный киносайт: парсит **два источника в один каталог**, складывает фильмы/сериалы
в PostgreSQL и воспроизводит их в плеере через iframe с кастомной обвязкой (выбор
озвучки, серий, навигация пультом — под старые Samsung Tizen Smart TV):

- **Amedia** — парсер сайта [amd.online](https://amd.online) (Animedia): работает
  **без токена и без логина**, отдаёт готовые iframe-ссылки на серии;
- **Kodik** — API [kodikapi.com](https://kodikapi.com): заглушка токена, активен,
  когда токен получен.

Режимы совмещены: один каталог, при совпадении названия данные сливаются в одну
карточку, **Amedia имеет приоритет**, озвучки Kodik остаются запасными вариантами.

## Стек

- PHP 8.4 + Symfony 7.4 (Twig, Doctrine ORM, Migrations)
- PostgreSQL 16
- nginx + php-fpm в Docker
- `symfony/http-client` — HTTP-клиент (Kodik API и HTML amd.online)

## Быстрый старт

```bash
# один раз: внешний том для PostgreSQL (живёт вне compose, переживает
# пересоздание контейнеров и `docker compose down -v`)
docker volume create films_database_data

docker compose up -d --build
docker compose exec -u daikzlex app php bin/console doctrine:migrations:migrate --no-interaction
```

Сайт: <http://localhost:8081> (порт меняется переменной `APP_PORT` в `.env`).

База данных хранится во внешнем томе `films_database_data`, поэтому `docker compose
down`, пересборка образа и `down -v` её не удаляют. Стереть данные можно только явно:
`docker volume rm films_database_data` (после `docker compose down`).

## Amedia (amd.online) — основной источник, без токена

Сайт не имеет API — парсер читает HTML (DOM/XPath), поэтому требует браузерный
User-Agent (задан в `.env`). Переменные окружения:

```
AMD_ONLINE_BASE_URL=https://amd.online
AMD_ONLINE_USER_AGENT="Mozilla/5.0 ..."   # иначе сайт отдаёт 404-страницу
AMD_ONLINE_DELAY_MS=250                   # пауза между запросами
```

```bash
# импорт каталога по дате редактирования (/f/sort=editdate/order=desc/) —
# свежие апдейты первыми, вся пагинация до 417 стр.
# --no-debug обязателен для полного обхода: иначе профайлер Doctrine копит
# backtrace всех запросов и процесс падает по памяти.
docker compose exec app php bin/console --no-debug amd:sync
docker compose exec app php bin/console --no-debug amd:sync --max-pages=10   # только 10 страниц
docker compose exec app php bin/console amd:sync "/" -s                      # блок «Новые аниме», только новые
docker compose exec app php bin/console amd:sync "/anime/god/2026/" -s       # другой раздел, только новые

# один тайтл по URL
docker compose exec app php bin/console amd:import https://amd.online/5768-psajren.html

# поиск по сайту и импорт найденного
docker compose exec app php bin/console amd:search "Реинкарнация" --limit=5

# очистка каталога (озвучки и серии удаляются каскадно)
docker compose exec app php bin/console app:titles:clear             # спросит подтверждение
docker compose exec app php bin/console app:titles:clear --force     # удалить всё без вопроса
docker compose exec app php bin/console app:titles:clear --source=amedia -f

# связка сезонов одного произведения (разово; далее её проставляет сам amd:sync)
docker compose exec app php bin/console app:seasons:link
```

Популярные разделы каталога: `/`, `/anime/tip/фильм/`, `/anime/tip/тв-сериал/`,
`/anime/tip/ova/`, `/anime/tip/ona/`, `/anime/god/2026/`, `/ongoingi/`.

Что импортируется: метаданные (название, оригинал, год, жанры, постер, описание),
список серий с iframe-ссылками (`aser.pro`), озвучки Kodik с вкладки Kodik
(`kodikplayer.com`, параметры season/episode подставляются в ссылку самим парсером)
и вкладка CDN (сохраняется как ссылка, в iframe не встраивается — у CDN-плеера
собственный JS-компонент, на старом Tizen он не играет).

Если тайтл с таким же названием (и годом) уже есть из Kodik — данные **сливаются**
в существующую карточку, амедия-плеер получает приоритет 1000 и идёт первым.

## Токен Kodik (второй режим)

Токен — заглушка. Получите его на kodikapi.com и пропишите в `.env` или `.env.local`:

```
KODIK_API_TOKEN=ваш_токен
```

Без токена команды `kodik:*` вернут ошибку — это нормально, работает Amedia.

## Команды Kodik

```bash
# поиск без сохранения (отладка)
docker compose exec app php bin/console kodik:search "Интерстеллар"

# импорт из выдачи в БД
docker compose exec app php bin/console kodik:import "Интерстеллар"
docker compose exec app php bin/console kodik:import --type=serial --year=2023 --page=2

# обновить серии/озвучки у уже импортированных сериалов
docker compose exec app php bin/console kodik:sync
docker compose exec app php bin/console kodik:sync --kodik-id=xxxxxx
```

## Демо-данные (без токена)

Чтобы посмотреть интерфейс до получения токена:

```bash
docker compose exec app php bin/console app:seed-demo
docker compose exec app php bin/console app:seed-demo --purge   # очистить и пересоздать
```

## Страницы

| Маршрут          | Описание                                              |
|------------------|-------------------------------------------------------|
| `/`              | Каталог: поиск, фильтр по типу, пагинация             |
| `/watching`      | Раздел «Смотрю»: отмеченные тайтлы                    |
| `/watched`       | Раздел «Просмотрено»: запускали, но не в «Смотрю»     |
| `/title/{id}`    | Карточка: мета, рейтинги, озвучки и серии             |
| `/watch/{id}`    | Плеер: прокси-фрейм источника + панель и оверлеи      |
| `/player/frame`  | Прокси-фрейм: HTML плеера источника через наш origin  |
| `/player/api`    | Шлюз AJAX плеера к его собственному API (нет CORS)    |

Источник тайтла виден в карточке: `source` в БД (`amedia` — приоритетный,
`kodik` — второй режим).

### Раздел «Смотрю»

Список тайтлов, которые вы смотрите. Флаг хранится в самом тайтле
(`titles.watching` + `titles.watching_at`), поэтому импорт/синк его не затирают.

- кнопка **«+ Смотрю» / «✓ В «Смотрю»»** на карточке тайтла и **над плеером**
  (в шапке и в надстройке озвучки) — переключает флаг;
- на странице плеера переключение идёт AJAX-ом (`POST /watching/{id}/toggle`),
  без перезагрузки — воспроизведение не прерывается;
- в шапке сайта — ссылка **★ Смотрю** со счётчиком;
- на странице `/watching` — сетка карточек с прогрессом и пустое состояние.

### Раздел «Просмотрено»

Тайтлы, которые запускали хотя бы раз (есть прогресс хотя бы по одной серии),
но **не** добавили в «Смотрю». Отдельная страница `/watched`, ссылка
**✓ Просмотрено** в шапке; сортировка — по свежести просмотра.

- отдельного флага нет: прогресс и так хранится в озвучках
  (`translations.last_episode` / `last_watched_at`), поэтому в раздел попадает
  всё, что запускалось;
- добавление в «Смотрю» убирает тайтл из «Просмотрено» — списки не пересекаются;
- за новыми сериями и продолжениями такие тайтлы не следят: и «Новые серии»
  (`findNewEpisodes()` → `watchingIds()`), и «Вышло продолжение»
  (`findNewSeasons()`) строятся только по тайтлам из «Смотрю».

Выборка — `TitleRepository::searchCatalog()` со `scope = SCOPE_WATCHED`:
`watching = false` плюс `EXISTS` прогресса. Условие сделано через `EXISTS`, а не
join по озвучкам, — join размножил бы строки и сломал пагинацию.

## Сезоны (связка тайтлов)

Продолжения одного произведения («Рон Камонохаси: Невменяемый детектив» и
«Рон Камонохаси: Невменяемый детектив 2») остаются отдельными карточками, но
связываются между собой: в карточке появляется блок **«Сезоны»** со ссылками на
остальные сезоны — по возрастанию.

Связка строится по названию (`App\Service\SeasonLinker`): убирается хвост с
номером сезона (`… 2`, `… 10`, римское `… III`, `… сезон 2` / `… Season 2`) и
части (`… Часть 2`, `… Часть II`), остаток нормализуется в ключ франшизы
(`titles.franchise`), а номер сезона/части ложится в `titles.season_number` и
`titles.season_part`. Тайтлы с одинаковым `franchise` — это сезоны и части одного
произведения; в блоке они идут по возрастанию, части помечаются отдельно
(«Сезон 1, часть 2»). Названия, где число — часть имени («Айшилд 21», «АКБ0048»),
сезоном не считаются.

```bash
# разово проставить/пересчитать связку по всему каталогу
docker compose exec app php bin/console app:seasons:link
```

Дальше это поведение встроено в обычный `amd:sync`: при импорте тайтла `franchise`
и номера выставляются автоматически, отдельный прогон не нужен (команда нужна
для разовой первичной связки уже импортированного каталога или после правок
разбора).

## Новые серии и «Вышло продолжение»

Сверху главной и страницы «Смотрю» — два блока, оба **над** выбором типа аниме:

- **«Новые серии»** — по тайтлам из «Смотрю»: вышедшие непросмотренные серии
  после последней просмотренной (серии-заглушки `do=nz` не в счёт). Клик ведёт
  сразу на нужную серию в плеере.
- **«Вышло продолжение»** — новые сезоны/части произведений, у которых
  **досмотрен** предыдущий сезон: «вы досмотрели S3 — вышел S4». Клик ведёт на
  карточку нового сезона.

Оба блока строятся только по тайтлам из «Смотрю»: «Просмотрено» — это просто
история запусков, за ней не следим.

Детекция «Вышло продолжение» (`TitleRepository::findNewSeasons()`):

1. по тайтлам **из «Смотрю»** с прогрессом определяется, какие сезоны досмотрены —
   последняя просмотренная серия не меньше последней **вышедшей** серии этого
   сезона (строгий порог: сезон именно закончен);
2. по каждой франшизе берётся самый дальний досмотренный сезон;
3. продолжение — ближайший по сезону/части тайтл той же франшизы, строго дальше
   досмотренного, у которого есть вышедшие серии, который ещё не начат, и который
   **появился в каталоге за последние 30 дней**.

Чтобы «вечные» напоминания о старых сезонах не копились, у `Title` есть
`first_seen_at` — когда тайтл впервые попал в каталог. Ставится один раз при
первом импорте и не меняется при повторных `amd:sync`. Существующие на момент
внедрения тайтлы помечены «год назад» (миграция `Version20261012130000`), поэтому
уведомления начинают приходить на реально новые сезоны, а не на весь каталог
разом. Окно в 30 дней при желании меняется в вызове `findNewSeasons()`.

## Дата обновления тайтла

Свежесть карточки на главной определяется `last_synced_at` (сортировка по нему —
сразу после года). `amd:sync` обновляет её, **только если импорт реально что-то
поменял**: появились серии или озвучки, изменились метаданные/ссылки. Обычный
обход каталога, при котором тайтл лишь перечитан без изменений, дату не трогает —
иначе весь каталог после каждого прогона всплывал бы наверх выдачи. Реализация —
сравнение снимка содержимого тайтла (метаданные + озвучки + серии) до и после
правок: `AmediaSync::contentSnapshot()`.

## Плеер: прокси-фрейм

Страница плеера источника (aser.pro, kodik и т.д.) **не встраивается напрямую**,
а загружается через наш маршрут `GET /player/frame?url=…` и отдаётся с нашего
origin (`PlayerFrameController` → `Service/Proxy/PlayerProxy`):

- сервер забирает HTML по HTTP-клиенту (с Referer `amd.online`, повторы при
  сетевых сбоях/429/5xx) и **вырезает из него рекламу и трекеры**: теги по
  домену (`AD_URL_RE`: doubleclick, googlesyndication, adfox,
  `yandex.ru/ads` — SDK рекламы Amedia, serving-sys, buzzoola, ufouxbwn,
  snsv.ru, `mc.yandex.ru`/Метрика и т.п.) и по имени в `src`
  (`AD_SCRIPT_SRC_RE`: `/adsbygoogle.js`, `advert`, `vast`, `metri[ck]a`, …),
  `<noscript>` с трекинг-пикселем; плюс выключает `forceAdvertCount` в
  настройках плеера Kodik;
- инъекция в порядке: `window.__cinemaPlayerHost` →
  `<script src="/js/player-shim.js">` → инлайн-селекторы рекламы →
  `<base href="…">` (все относительные ссылки плеера становятся ссылками
  источника);
- статика версионируется по mtime (`asset_v()` в Twig, `?v=` у shim) — иначе
  правки залипают в кеше браузера;
- заглушка «Смотрите на сайте» (<800 байт) и не-http ссылки → `302` на
  исходный сайт, ошибки логируются префиксом `[player-proxy]`
  (`docker compose logs app`).

`GET/POST /player/api?url=…` (`PlayerProxy::passthrough`) — шлюз для AJAX
плеера к **его собственному хосту**. Документ плеера у нас на своём origin,
поэтому его запросы к API апстрима (например `POST /ftor` у Kodik) стали бы
кросс-доменными, а CORS у этого API нет — браузер режет ответ и видео не
грузится. shim переписывает такие URL на `/player/api`, а сервер ходит к
апстриму с Referer `amd.online`. Медиа и статику шлюз не трогает (по
расширению): у них обычно есть CORS, а проксирование плейлистов ломает
разбор относительных ссылок в них. Зато из JSON-ответов API шлюз **вырезает
рекламные поля** (`vast`, `reserve_vast`, `advert_script` — у Kodik это
`POST /ftor`): рекламному модулю плеера нечего проигрывать, ролик не
появляется вовсе.

Что делает `public/js/player-shim.js` внутри фрейма:

- **`window.__cinemaPlayer`** — то, что тянет родительская обвязка: готовность,
  время/длительность, `seek` на секунду, play/pause, «закончилось»;
- **автостарт**: страницы плеера ждут тапа («Нажмите для просмотра»), а на ТВ
  пульта тапа нет — шим сам «нажимает» кнопку старта (у Kodik `<video>`
  создаётся только после клика по оверлею → запрос `/ftor`), а затем запускает
  видео, как только известна длительность (при запрете без жеста — ждёт первой
  клавиши/клика);
- **шлюз к API плеера**: AJAX к собственному хосту плеера заворачивает на
  `/player/api` (см. выше);
- **рекламный брандмауэр** — до попытки загрузки: `fetch`/XHR (fast-fail:
  `readyState=4`, `status=0`, события `error`/`loadend`), `src`-сеттеры,
  `setAttribute`, `innerHTML`/`insertAdjacentHTML`, `textContent` для `<style>`,
  CSSOM (`background`/`backgroundImage`/`setProperty`/`cssText`/`insertRule`),
  `sendBeacon`, `WebSocket`; плюс вырезание рекламных узлов по селекторам
  (`window.__cinemaAdSelectors`).
- **фуллскрин**: нативный `requestFullscreen`/`exitFullscreen` (и вендорные
  префиксы, плюс `video.webkitEnterFullscreen`) перехватывается и передаётся
  родителю через `window.__cinemaFullscreen`. Так **любой** разворот из плеера
  (кнопка, двойной клик, клавиша `f`, внутренний API) идёт через один
  обработчик; родитель запрашивает настоящий полноэкранный режим браузера.

Родительская обвязка (`public/js/player.js`, ES5) живёт на `/watch/{id}`:

- адрес отражает выбор: `?t=<озвучка>&s=<сезон>&e=<серия>`; при загрузке эти
  параметры имеют приоритет над сохранённым состоянием — ссылку на конкретную
  серию можно сохранить/переслать;
- транспорт панели `−10 / ▶ / +10`, клик по строке прогресса — **точный seek**,
  индикатор `12:34 / 23:38`, полный экран (нативный — прячет адресную строку
  браузера; CSS-режим `fs-fake` только как резерв) — пока в отключённой
  панели, см. ниже;
- **полный экран**: сначала всегда честный нативный Fullscreen API — пробуем
  `document.documentElement` (весь документ; так адресная строка браузера
  скрывается, а картинка плеера не «чернеет», в отличие от разворота контейнера
  на Tizen), затем сам `<iframe>`, затем `#frame-box`; если API нет или запрос
  отклонён — включаем CSS-режим `fs-fake`. В полноэкранном режиме шапка сайта
  и верхняя панель плеера скрываются классом `fs-active` на корне документа
  (ставит player.js по событию `fullscreenchange`), поэтому плеер занимает весь
  экран и на старом WebKit, где псевдокласс `:fullscreen` не срабатывает;
- **оверлей быстрого переключения серий** (`#quick-ep`) поверх плеера:
  `◀`/`▶`, выпадающий список и **числовое поле «№»** — введите номер серии и
  нажмите Enter, чтобы перейти сразу (не листая длинный список):
- клавиши навешиваются и на `frame.contentDocument` (фрейм same-origin) —
  пульт работает при фокусе внутри плеера;
- при окончании серии — авто-переход к следующей.

### Пульт Tizen / клавиатура

- `OK` — **старт/пауза** (полная панель временно отключена, см. ниже);
- `←` / `→` — **перемотка ±10 с** (внутрь фрейма);
- `PageUp` / `PageDown` — предыдущая/следующая серия;
- `Пробел` — старт/пауза; медиа-кнопки Tizen: `415` play, `413` pause,
  `10252` play/pause, `412`/`417` перемотка;
- **синяя** кнопка — к сетке серий (пока панель отключена — не активна);
- **красная** — к карточке тайтла; **зелёная / жёлтая** — пред./след. серия;
- `↩ / Return / Esc` — назад / выход из полного экрана;
- при окончании серии — **авто-переход к следующей**.

### Панель (оверлей поверх плеера)

> **Временно отключена** по запросу: в `public/js/player.js` стоит
> `PANEL_ENABLED = false`. Вёрстка `#control-panel` в `watch.html.twig` и весь
> код панели сохранены — для возврата достаточно выставить `PANEL_ENABLED = true`.
> Пока панель выключена, озвучку/серию можно выбрать через URL-параметры
> (`?t=&s=&e=`), а серию — надстройкой `#quick-ep` (в т.ч. полем «№») и
> клавишами PageUp/PageDown / зелёной/жёлтой.

Зоминается в `localStorage`: озвучка/сезон/серия и **позиция просмотра**
(`kino:title:{id}`), позиция восстанавливается при возврате.

> Код плеера намеренно написан на консервативном ES5 (без стрелок и шаблонных
> строк) и с крупными фокус-рамками — это важно для старых браузеров Tizen.
> Кнопки панели не меньше ~48 px по высоте.

## Бэкап и перенос БД (dump / restore)

Готовые скрипты в `docker/`:

```bash
# экспорт: backups/cinema-<дата>.dump (custom-формат pg_dump, сжатый)
./docker/db-dump.sh

# импорт на новом сервере: база пересоздаётся «начисто» из дампа
./docker/db-restore.sh backups/cinema-20261012-013924.dump
```

То же вручную:

```bash
# экспорт
docker compose exec -T database pg_dump -U cinema -d cinema -Fc -Z9 > cinema.dump

# импорт в текущую базу (объекты пересоздаются на месте)
docker compose exec -T database pg_restore -U cinema -d cinema --clean --if-exists --no-owner < cinema.dump
```

`db-restore.sh` останавливает `app`, делает `dropdb`/`createdb` и заливает дамп
через `pg_restore` (данные остаются в том же томе `cinema_database_data`). Если
код новее дампа — догоните схему:
`docker compose exec app php bin/console doctrine:migrations:migrate --no-interaction`.

## Регулярный парсинг обновлений (cron)

Обёртка `docker/sync-updates.sh` запускает `amd:sync --max-pages=10` (каталог
отсортирован по дате редактирования — свежие вышедшие серии первыми), пишет лог
в `var/log/amd-sync.log` и не даёт запуститься второму экземпляру параллельно
(`flock`).

Пример crontab лежит в `docker/crontab` — **дважды в день, 06:00 и 18:00**:

```cron
0 6,18 * * * /opt/cinema/docker/sync-updates.sh
```

Установка на VPS (путь подставить свой):

```bash
crontab /opt/cinema/docker/crontab    # или вставить строку в crontab -e
crontab -l
tail -f /opt/cinema/var/log/amd-sync.log
```

Интервал/объём меняются переменными: `PAGES=25 docker/sync-updates.sh` или
правкой расписания в `docker/crontab`.

## Ограничение памяти

Два уровня лимита:

- **контейнер** — в `docker-compose.yml` у сервисов `database` и `app` стоит
  `mem_limit: 1g`: контейнеры не съедят больше гигабайта (актуально для VPS);
- **PHP** — `memory_limit = 768M` из `docker/php.ini` (монтируется в
  `/usr/local/etc/php/conf.d/zz-app.ini`). Дефолтных 128M не хватает на полный
  обход каталога `amd:sync` — PHP упирается в лимит. 768M держим ниже `mem_limit`
  контейнера, чтобы при нехватке памяти PHP падал с понятной ошибкой, а не
  убивался OOM-killer'ом.

Сам `amd:sync` освобождает память после **каждого** тайтла, а не копит её до
конца: сбрасывает identity map Doctrine (`$em->clear()`) и сразу собирает
осиротевшие циклические ссылки сущностей (`gc_collect_cycles()`). Поэтому расход
памяти не растёт с числом обработанных тайтлов. По ходу обхода прогресс
печатается после каждой страницы:

```
Страница 1: импортировано 12, пропущено 0, с ошибками 0, новых серий 168.
```

Если полного парсинга всё же не хватает — поднимите **оба** значения (`mem_limit`
у сервиса `app` и `memory_limit` в `docker/php.ini`) и перезапустите:
`docker compose up -d app`.

Полный обход всё равно полезно запускать с `--no-debug` — Doctrine-профайлер
копит backtrace и заметно увеличивает расход памяти:

```bash
docker compose exec app php bin/console --no-debug amd:sync
```
